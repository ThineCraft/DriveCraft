Set up DriveCraft

Microsoft 365 only lets a registered application sign people in. Before anyone in your organization can use DriveCraft, someone creates its app registration, once. It takes about five minutes.

Who does this: someone who may create app registrations in your Microsoft 365 organization, usually an administrator. Everyone else only needs the two IDs it produces; they are not secret.

1. Create the registration

  1. Sign in to the Microsoft Entra admin center and open App registrations (search for it at the top of the page if you cannot see it).
  2. Choose New registration.
  3. Name: DriveCraft.
  4. Supported account types: Accounts in this organizational directory only.
  5. Redirect URI: choose the platform Public client/native (mobile & desktop) and enter http://localhost.
  6. Choose Register.
  7. On the overview page, copy the Application (client) ID and the Directory (tenant) ID.

2. Add the permissions

Open API permissions, choose Add a permission, then Microsoft Graph, then Delegated permissions, and add these five:

PermissionWhat DriveCraft uses it for
Files.Read.AllReading libraries, for a read-only sign-in.
Files.ReadWrite.AllUploading, changing and deleting files, for two-way sync and uploads.
Sites.Read.AllFinding SharePoint sites and libraries, and reading who may open what.
User.ReadShowing who is signed in.
offline_accessStaying signed in between runs.

If your organization does not let people approve apps for themselves, an administrator then chooses Grant admin consent on the same page. Doing it anyway saves everyone a consent prompt.

Optional: to sign in with a code on another device from the command line, open Authentication and set Allow public client flows to Yes.

3. Tell DriveCraft

Start DriveCraft. On the Set up DriveCraft screen, paste the Application (client) ID and the Directory (tenant) ID, then choose Save. Give the same two IDs to everyone else in your organization who will use it.

From the command line instead:

drivecraft setup --client-id APPLICATION-ID --tenant TENANT-ID

What this allows

  • These are delegated permissions: DriveCraft acts as the person who signs in, and reaches only what that person can already reach.
  • The registration holds no password or secret, and DriveCraft has no access of its own.
  • It is your organization's registration. To stop DriveCraft signing anyone in, open Enterprise applications, choose DriveCraft, and under Properties set Enabled for users to sign in to No, or delete the registration.
