Open-source sync for SharePoint and OneDrive for work

Keep every file in reach and under your control.

DriveCraft keeps SharePoint document libraries and OneDrive for work in step with folders on your computer. It is built for libraries far larger than the usual clients are comfortable with, and it tells you plainly what it is doing.

Working prototype for Windows Everything shown on this page runs today. Try it on a test library first: it is not finished, and the installer is not yet code-signed.

The proposition

Built to stay understandable, and yours.

Most people still use SharePoint like a shared drive. DriveCraft meets them there: files stay whole on disk, every run can be previewed and is logged, and anything it alters on your computer can be put back with one switch.

Working today

What DriveCraft already does.

01

Three ways to connect

Sync, Archive, or Ingest

Two-way sync for everyday work. Archive for a complete download-only copy that never changes the library. Ingest to move a folder or file server into a library without touching the source.

02

Large libraries

No file-count ceiling

A catalog on your computer tracks every file, so there is no fixed limit to hit. DriveCraft paces itself to what the server will accept instead of being thrown back. A long run says what it is doing, with counts and the folder it is in, and estimates the time left from the speed of the last hour.

03

Nothing by surprise

Preview, then act

Preview any run before it happens. Large deletions wait for your confirmation. A file changed in both places is never overwritten: your version is kept beside the library’s.

04

Tested at scale

The computer restarted in the middle of the run, and DriveCraft carried on from where it had stopped. This test was an upload; syncing a library that large down to a computer is still to be proven.

05

The first scan, once

Seeds that respect permissions

An owner can publish a seed into the library, so other computers skip the slow first scan of a very large library. Each computer then removes what its own user may not open, and asks the library where the seed cannot settle it. So far this is tested against a stand-in server, not yet with a second real user.

06

No false alarms

Skipped, not failed

A file you may not open is skipped quietly instead of failing on every run, and is picked up again once you are given access. A file your antivirus blocks is reported in plain words, with what to do about it.
