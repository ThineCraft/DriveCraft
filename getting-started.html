ThineCraft project guide

DriveCraft: getting started

Status: Early prototype. The core passes its automated tests against a stand-in server, and the command line and the desktop app have each had a manual trial against a small SharePoint Online test library (two-way sync between two folders, including a conflict). It has not been tried on a large or heavily used library. Treat first runs as a trial and follow the order below.

Project scope

What the prototype does

  • Signs in with a work or school account through the browser, with an optional read-only sign-in that cannot change the server.
  • Connects a SharePoint document library, or your OneDrive for work, to a local folder whose name you choose.
  • Runs in three modes: Archive (download only), Sync (two-way), and Ingest (upload a disk source, following symbolic links, never changing the source).
  • Keeps its catalog in a local SQLite database and asks the server only for changes after the first scan. An interrupted first scan resumes where it stopped.
  • Waits as long as the server asks when it is throttled, then slows its own pace so that it is asked less often.
  • Warns about long paths and about names SharePoint rejects.
  • Keeps both versions when a file changed in both places, and holds back large deletions until you confirm them.
  • Checks a file out and in from the command line.
  • Publishes a seed: a snapshot of a library's file list, stored in the library, that lets another computer skip the first full scan.
  • A desktop app with a tray icon over the same core: sign in, connect a library, choose the mode, preview and run a sync, and see activity, conflicts and warnings.

Not built yet

  • Files on demand (placeholders). Every file in a connected library is downloaded in full.
  • File manager integration: context-menu check out and check in, status icons, custom folder icon.
  • Taking over the browser Sync button, and sign-in with the Windows login without a browser.
  • Linux and macOS builds have not been tried. The code is written to be portable.
  • A background service separate from the desktop app. Synchronization runs while the desktop app is running, in its window or in the tray (with Keep in sync on), or when you run the command.
  • An installer. The desktop app is run from the build folder for now.

1. Build

With Rust installed, from this folder:

cargo build --release

The command-line program is target\release\drivecraft.exe. The commands below assume it is on your path or that you run it from that folder.

To build the desktop app as well:

cargo build --release --workspace

The desktop app is target\release\drivecraft-app.exe.

2. Create the app registration

Microsoft 365 only lets a registered application sign users in. This is done once per tenant, in the Microsoft Entra admin center. Depending on how the tenant is configured, you may need an administrator to do it or to approve the permissions.

  1. Go to App registrations and choose New registration.
  2. Name: DriveCraft (test).
  3. Supported account types: Accounts in this organizational directory only.
  4. Redirect URI: choose the platform Public client/native (mobile & desktop) and enter http://localhost.
  5. Choose Register. Copy the Application (client) ID and the Directory (tenant) ID from the overview page.
  6. Under API permissions, add these Microsoft Graph delegated permissions: Files.Read.All, Files.ReadWrite.All, Sites.Read.All, User.Read, offline_access. If the page shows that administrator consent is required, an administrator must choose Grant admin consent.
  7. Optional, only for signing in with a code on another device: under Authentication, set Allow public client flows to Yes.

These are delegated permissions: DriveCraft acts as the person who signs in and can reach only what that person can already reach. It holds no secret and has no access of its own.

Then tell DriveCraft about it:

drivecraft setup --client-id APPLICATION-ID --tenant TENANT-ID

3. First run: read only

Start with a small test library and a sign-in that cannot change anything on the server.

drivecraft login --read-only
drivecraft connect "https://YOURTENANT.sharepoint.com/sites/YOURSITE/Shared Documents" C:\DriveCraft\Test
drivecraft sync Test --dry-run
drivecraft sync Test
drivecraft status Test
  • The address is the one in the browser when you have the library open. View pages and query strings on the end are removed for you.
  • The last part of the local folder becomes the connection's name (Test here). Use --name to choose another.
  • connect uses Archive mode unless told otherwise: it downloads and never uploads.
  • --dry-run lists what would happen and changes nothing.

Then change, add, rename and delete a few files in the library through the browser and run drivecraft sync Test again. The local folder should follow.

4. Two-way synchronization

Once Archive behaves, sign in with write access and switch the connection:

drivecraft login
drivecraft mode Test sync
drivecraft sync Test --dry-run
drivecraft sync Test

To keep it running: drivecraft sync Test --every 60.

How Sync protects your files

  • A file changed here and on the server is never overwritten. Your version is kept beside it as name (local copy) and both end up in both places.
  • An upload is refused by the server if its copy changed since DriveCraft last saw it.
  • If more than 20 items are missing locally, or the folder is empty, nothing is deleted on the server until you run with --confirm-deletes. If the folder itself is missing, the run stops.
  • Items deleted on the server by DriveCraft go to the SharePoint recycle bin like any other deletion.
  • Office lock files, temporary files and symbolic links are not uploaded.

5. Migrating a folder from disk (Ingest)

drivecraft connect "LIBRARY ADDRESS" D:\OldFileServer\Projects --mode ingest --name Migration
drivecraft sync Migration --dry-run
drivecraft sync Migration
  • The source folder is only read. DriveCraft keeps its records in its own data folder, not in the source.
  • Symbolic links are followed and the files they point to are uploaded.
  • A file that already exists on the server with the same content is recognised and skipped. One with different content is reported and left alone.
  • Running again uploads only what was not uploaded before. Add --update to send new versions of source files that changed.

Seeds: sparing other computers the first scan

The first scan of a large library is slow, because every item has to be read from the server. A seed lets one computer do that once for everyone.

drivecraft seed NAME
  • This stores a compressed snapshot of the library's file list in a .drivecraft folder at the top of the library. In the desktop app it is Publish a seed, behind the settings button beside the library's name. It needs write access.
  • Any computer that later connects to that library looks for a seed on its first synchronization. If it finds one, it loads it and asks the server only for what changed since. Nothing has to be copied between computers by hand.
  • A seed is a starting point only. It holds names, sizes and identifiers, not file contents and not settings. After the first synchronization each computer keeps itself current on its own.
  • Publish again whenever you like; the new seed replaces the old one. A seed that is old still works, as long as the server still honours its bookmark; if not, DriveCraft scans in full.
  • Anyone who can open the library can see the .drivecraft folder and so the names of every file in the seed. In a library where some folders are restricted to certain people, think before publishing one.
  • drivecraft sync NAME --no-seed ignores a seed and scans in full.

The desktop app

Run target\release\drivecraft-app.exe. It uses the same settings, sign-in and catalog as the command line, so libraries connected in one appear in the other.

  • On first run it asks for the application ID, then lets you sign in read-only or with write access. You can change the access level later from the account menu.
  • Connect a library takes the library's address, a local folder and a mode. Check shows which library the address points to before you connect.
  • Preview changes lists what a run would do and changes nothing. Sync now runs it.
  • Switching a library to Sync, deleting held-back items from the library, and disconnecting each ask for confirmation first.
  • Keep in sync keeps libraries current while the app is running. A two-way library is synchronized a few seconds after a file in its folder changes, and every library is checked against the server once a minute. An ingest is never run this way; you start it yourself.
  • Start with Windows starts DriveCraft in the tray, without opening its window, each time you sign in to the computer. The setting is for your Windows account only.
  • Only one copy of DriveCraft runs. Starting it again brings the running copy's window to the front.
  • File Explorer. In a library's settings, Show in File Explorer lists its folder in File Explorer's side pane and puts a status icon beside every file and folder: a green tick when it matches the library, and the pending arrows from the moment you change it until DriveCraft has sent the change. You can give the folder its own name and icon there; both are for this computer only and change nothing in the library. Right-clicking a file inside the folder offers Check out and Check in (on Windows 11, under Show more options); DriveCraft confirms each with a notification. The files stay ordinary, complete files on your disk. The icons are shown while DriveCraft is running. Turning the switch off makes the folder an ordinary folder again. An ingest source is never changed, so it has no such switch.
  • Checked-out files. When files in a library are checked out, a bar on its page says how many and how many are yours. View lists them with who holds each one; for your own you can add a comment and Check in from there. The list comes from the server after every synchronization, so it includes files other people checked out, and it updates at once when you check out or in through DriveCraft. In a folder shown in File Explorer, a checked-out file also carries a padlock with the holder's name.
  • Recycle bin. The link at the bottom of a library's page opens what was deleted from that library and is still in the site's recycle bin, newest first. Start typing to find something: any part of the name, the folder it was in, or the person who deleted it, in any order; the matching part is highlighted. The filters narrow it by when it was deleted, who deleted it, the kind of file, and this library or the whole site, and you can order by date, name or size. Tick one or more items and choose Restore to put them back where they were; Sync now then brings them back to this computer. The list is kept while DriveCraft runs, so opening it again is immediate, and it is refreshed from the server each time. DriveCraft never empties the bin or deletes from it. The second-stage bin is left to site administrators, in SharePoint.
  • Problems. When something in a library needs your attention, a bar appears on its page and its dot in the list turns amber or red. View lists each item with the reason and what to do: files that could not be transferred, files changed in both places, names the library refuses, deletions waiting for your confirmation, and a run that could not finish. Show in folder takes you to the file. Most problems clear by themselves once they are fixed and the library synchronizes again. Notices (a copy that was kept, a long path, a file kept after it was deleted in the library) stay until you dismiss them or the file is gone.
  • The window has no title bar. Drag it by the header, and use the one button at the top right to put it away in the system tray, where DriveCraft keeps running. Click the tray icon to bring it back; its menu also has Sync now and Quit.
  • The mode switch and Disconnect are behind the settings button beside the library's name.
  • The theme switch at the bottom right chooses System, Light or Dark. Each theme is a set of named colours in app/ui/styles.css, so further themes can be added as another set.

The interface is built with Tauri: the core is Rust and the screens are HTML in app/ui. Opening app/ui/index.html in a browser shows the interface with sample data, for design work.

Other commands

  • drivecraft explorer NAME shows a library's folder in File Explorer with status icons; --label and --icon set its name and icon on this computer, and --off undoes it. The right-click menu is set up by the desktop app.
  • drivecraft checkouts lists the files that are checked out in each library, and by whom.
  • drivecraft recycle-bin NAME lists what was deleted from a library and is still in the recycle bin; --find "words" narrows it to items whose name, folder or deleter contain every word, --restore ID puts an item back, and --whole-site lists the whole site's bin.
  • drivecraft problems lists what needs your attention in each library, the same list the desktop app shows. Add a connection's name for one library, and --dismiss-notices to clear the notices.
  • drivecraft doctor shows the setup, the sign-in, the network connection in use, and whether Windows long path support is on. When it is off, DriveCraft says so and carries on; the setting belongs to the computer's administrator and DriveCraft does not change it.
  • drivecraft checkout FILE and drivecraft checkin FILE --comment "..." for a file inside a connected folder.
  • drivecraft logs shows where the log files are. Every run, from the command line or the desktop app, is recorded there with timestamps: each action, each time the server throttled or a request was retried, progress with time remaining, and at the end the timings, request counts and peak memory. Logs hold file names and paths but never sign-in tokens, and are kept for 30 days.
  • drivecraft network --bind 192.168.1.9 makes DriveCraft send through the connection that has that address, on a computer with more than one. It applies to the command line and the desktop app, and changes nothing in the computer's own network settings. drivecraft network --clear undoes it.
  • drivecraft sync NAME --parallel 8 transfers more files at once (1 to 16; the default is 4).
  • drivecraft list, drivecraft whoami, drivecraft logout, drivecraft disconnect NAME (leaves local files in place).

DriveCraft keeps its catalog, settings and saved sign-in in %LOCALAPPDATA%\ThineCraft\DriveCraft. On Windows the saved sign-in is encrypted with your Windows account. Set the DRIVECRAFT_HOME environment variable to use a different folder.

Running the tests

cargo test

The tests run the engine against an in-memory file server, and the Microsoft Graph client and sign-in against a local stand-in. They check DriveCraft's own behaviour. They cannot show that Microsoft 365 responds the way the stand-in does; only a run against a real tenant can.
