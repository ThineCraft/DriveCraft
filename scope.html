ThineCraft project scope

DriveCraft

Status: Early prototype. This document describes intended direction. A command-line client implementing part of it exists and passes automated tests against a stand-in server; it has had one manual trial against a small SharePoint Online test library and nothing larger. See Getting started for exactly what is and is not built.

Project website

Purpose

DriveCraft is the planned open-source OneDrive alternative for everyday synchronization, managed metadata, migration, and organization-controlled continuity across Linux, Windows, and macOS.

Confirmed direction

  • Desktop clients for Zorin OS and other Linux environments, Windows, and macOS.
  • A consistent view of files, sync state, versions, and managed metadata.
  • Rust as the implementation language, chosen for performance and for safe native integration with each operating system.
  • A local SQLite catalog, embedded in the client, designed to track far more than 100,000 files. Removing the practical file-count ceiling of the OneDrive sync client is a primary goal.
  • A catalog that separates the description of the server (items, identifiers, hashes, change bookmark) from the state of the individual machine (what is downloaded, pending local changes).
  • A per-library seed: a read-only snapshot of the server part of the catalog, stored inside the document library it describes, so that additional machines can skip the first full scan. It is a starting point for initial synchronization only; afterwards each machine keeps itself current independently.
  • Check out and check in of files directly from the file manager's context menu, with the checked-out state visible on the file.
  • A configurable local folder name for each synchronized library, independent of the site or organization title, so that long titles such as "Trinidad and Tobago Securities and Exchange Ltd." do not have to appear in local paths.
  • A configurable icon for each synchronized library as shown in the file manager.
  • The local folder name and icon are chosen on each machine and stored only there; they are not distributed through the library or its seed.
  • Native ShareCraft integration.
  • Microsoft Graph integration for SharePoint and OneDrive discovery, migration, backup, and controlled synchronization.
  • Access to a user's personal OneDrive on their work or school account, in addition to shared SharePoint libraries.
  • Three operating modes, set for each connection between a local location and a library:
    • Sync: two-way synchronization between the local folder and the library.
    • Ingest: one-way migration from an existing disk source into the library. DriveCraft reads the source, including the files that symbolic links point to, and uploads; it never writes, changes, or deletes anything in the source.
    • Archive: one-way egress from the library to local storage. DriveCraft downloads only and never uploads or changes anything on the server. When a file is deleted on the server it is also removed from the archive; recovery of deleted files relies on the server's recycle bin.
  • Single sign-on with the Windows login: on a Windows machine signed in with a work account, DriveCraft uses that account without asking for credentials again. Other platforms and unmanaged machines fall back to signing in through the browser.
  • DriveCraft acts as the signed-in user. It can reach only the sites, libraries, and files that user is already permitted to reach; it does not hold organization-wide access of its own on the desktop.
  • Long path handling: DriveCraft warns when a file's path is too long for the local system or for the server, and on Windows offers to turn on the operating system's long path support where that is possible.
  • A recycle bin view in the client, showing the user's deleted items and allowing them to be found and restored without using the SharePoint web interface. Users who are administrators of the site also see the second-stage recycle bin.
  • The client respects server throttling: it honours the wait times the server asks for and backs off, rather than retrying aggressively or working around limits.
  • When DriveCraft takes over from the Microsoft OneDrive client on a machine, it also takes over the "Sync" action in the SharePoint and OneDrive web pages, so that pressing Sync in the browser opens DriveCraft and adds that library.
  • Build order: DriveCraft works with OneDrive and SharePoint through Microsoft Graph first, so that people can try it against the files they already have and come to trust it; ShareCraft integration follows as ShareCraft takes shape.
  • Migration of files and metadata into ShareCraft or SharePoint.
  • An organization-wide offline copy on a server, NAS, or other privately controlled infrastructure.
  • Hybrid operation that combines cloud convenience with independent continuity and recovery.

Boundaries and non-goals

  • DriveCraft is not Windows-only and must treat Linux as a first-class platform.
  • It is not merely a backup utility; interactive synchronization, metadata, migration, and continuity are all core concerns.
  • It must support both ShareCraft-native environments and Microsoft 365 interoperability.
  • The offline copy is organization-controlled infrastructure, not an opaque vendor recovery tier.
  • Consumer OneDrive on personal Microsoft accounts is not supported; Microsoft 365 access is through work or school accounts only.
  • The desktop client does not embed or require PostgreSQL. A live catalog file is never shared between machines; only exported seeds are.
  • No implementation, benchmark, compatibility level, or production readiness is currently promised.

Expected integrations

  • ShareCraft document libraries, managed metadata, versions, permissions, and search.
  • Microsoft SharePoint and OneDrive through Microsoft Graph.
  • Local SQLite for durable file and metadata indexing on each client.
  • Servers, NAS devices, and private hosts for organization-wide offline copies.

Open decisions

  • Sync protocol, conflict handling, selective sync, placeholders, and offline semantics.
  • Filesystem integration and packaging strategy on each supported operating system.
  • SQLite schema, indexing, change detection, and performance targets beyond 100,000 files.
  • Seed details: file format, location and naming inside the library, refresh policy, and how entries are confirmed against the importing user's own access where folders have unique permissions.
  • Whether a Microsoft Graph change bookmark created by one user can be used by another; this must be tested against a real tenant and decides how a seeded machine catches up.
  • Whether ShareCraft exposes a Microsoft Graph-compatible file interface so that one client serves both backends. This depends on ShareCraft's own open decision on compatibility boundaries with Microsoft 365.
  • Database for the organization-wide offline copy; PostgreSQL is a candidate for that server-side component.
  • How context-menu actions, custom icons, and status indicators are delivered in each file manager (Windows Explorer, Linux file managers, macOS Finder), and what each platform permits.
  • How DriveCraft earns trust alongside the Microsoft OneDrive client: coexistence on the same machine, and whether a read-only or preview mode is offered before it is allowed to change files.
  • Taking over the browser Sync action: it relies on the link format Microsoft's web pages hand to the OneDrive client, which is undocumented and can change; and the OneDrive client may reclaim the action when it updates. How takeover is offered, kept, and handed back needs design.
  • Ingest details: handling of symbolic links that loop or point outside the source, whether a later run picks up only what changed in the source, and what happens to names and paths the server does not accept.
  • Archive details: whether earlier versions of files changed on the server are kept, and how the archive relates to the organization-wide offline copy.
  • Recycle bin details: which Microsoft interface provides listing and restore (Microsoft Graph coverage is limited, so the SharePoint REST interface may be required), how administrator status is determined, and whether permanent deletion is offered from the client at all.
  • Microsoft 365 sign-in and consent: the exact permissions requested, which of them an organization's administrator must approve once for the tenant, publisher verification for the ThineCraft app registration, and single sign-on equivalents on Linux and macOS.
  • How the organization-wide offline copy authenticates, since it runs without a signed-in user and would need access granted by an administrator.
  • Long path details: the thresholds that trigger a warning, whether the warning comes before or after a file is synchronized, how the Windows long path setting is applied when it needs administrator rights or is controlled by organization policy, and how to warn about programs that still cannot open long paths after the setting is on.
  • Metadata mapping and fidelity between ShareCraft, SharePoint, local filesystems, and offline copies.
  • Encryption, key ownership, retention, recovery, and administrative policy.

Guidance for AI contributors

  1. Treat cross-platform support, managed metadata, Microsoft Graph interoperability, and the offline organizational copy as core scope.
  2. Do not describe planned behavior as implemented or tested.
  3. Do not reduce DriveCraft to a consumer sync folder or a backup-only product.
  4. Prefer portable data, transparent state, recoverability, and infrastructure the organization can control.
  5. Develop and test Microsoft 365 integration against a dedicated test tenant, never against an employer's or customer's production tenant.
  6. Record new product decisions in this file before presenting them as settled scope.
